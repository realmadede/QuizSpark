# Production Deployment Guide

QuizSpark is fully configured for production deployment. Due to its architecture (a TanStack Start/Vite frontend and a Node.js/Socket.io backend), the recommended deployment strategy involves hosting the frontend on an edge/serverless platform (like Vercel) and the backend on a platform that supports long-running WebSocket connections (like Render, Fly.io, or Railway).

---

## 1. Deploying the Backend (Render / Fly.io / Railway)

Your backend needs to support persistent WebSockets, which makes standard serverless functions (like Vercel functions) unsuitable for the backend API.

1. **Create a Managed PostgreSQL Database**
   Provision a PostgreSQL database (Supabase, Neon, AWS RDS, etc.) and copy your connection string.

2. **Create a Redis Instance (Optional but Highly Recommended)**
   Provision a Redis database (Upstash, Render Redis, ElastiCache). This is required for distributed rate-limiting and quota enforcement across scaled backend pods.

3. **Deploy the Node.js Server**
   Connect your GitHub repository to your host (e.g., Render Web Service) and configure it as follows:
   - **Root Directory:** `backend`
   - **Build Command:** `npm install && npm run prisma:generate && npx prisma migrate deploy && npm run build`
   - **Start Command:** `npm run start`

4. **Set Backend Environment Variables**
   Configure these in your hosting dashboard:
   ```env
   NODE_ENV="production"
   DATABASE_URL="postgresql://user:password@host:port/dbname?sslmode=require"
   JWT_SECRET="generate-a-very-secure-random-string"
   FRONTEND_URL="https://your-frontend-domain.com"
   REDIS_URL="redis://your-redis-url"
   SMTP_EMAIL="your-system-email@gmail.com"
   SMTP_PASSWORD="your-app-password"
   PORT=5000
   ```

_(Keep note of the generated backend URL, e.g., `https://quizspark-backend.onrender.com`)_

---

## 2. Deploying the Frontend (Vercel)

QuizSpark's frontend uses Vite and TanStack Start, which Vercel supports natively. The repository already includes an `app.config.ts` file configured with the `vercel` preset to automatically build for the Vercel Edge.

1. **Import the Project into Vercel**
   Select the root directory of the QuizSpark repository.

2. **Configure Vercel Settings**
   - **Framework Preset:** `Other`
   - **Build Command:** `npm run build`
   - **Output Directory:** _(Leave Blank)_ - Vercel will auto-detect the `.vercel/output` directory generated by Nitro.

3. **Set Frontend Environment Variables**
   Add these variables in the Vercel dashboard to point the frontend to your newly deployed backend:

   ```env
   VITE_API_URL=https://quizspark-backend.onrender.com/api
   VITE_SOCKET_URL=https://quizspark-backend.onrender.com
   ```

4. **Deploy**
   Vercel will automatically build the client and server chunks, and deploy the application.

## Security & Infrastructure Checklist

- **HTTPS:** Ensure HTTPS is forced on your hosting provider. (QuizSpark enforces HSTS internally).
- **CORS:** Ensure `FRONTEND_URL` on the backend matches your domain perfectly (do not include trailing slashes).
- **Secrets:** Never commit `.env` files.
- **Source Maps:** Vite safely omits source maps during production builds by default. Do not change this unless integrating a private error tracking pipeline.
